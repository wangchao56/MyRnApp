# 开发环境安装与配置

> 状态：✅ 已落地（2026-05）  
> 适用：React Native **0.77.3** · macOS / Linux / Windows

本文说明本仓库如何通过脚本**安装系统工具**、**扫描路径**、**生成 `.env`**，以及日常开发命令与常见问题。

---

## 一、脚本与命令对照

| 命令 / 脚本 | 平台 | 作用 |
|-------------|------|------|
| **`pnpm setup`** | 全平台 | 安装系统依赖（可选）+ `pnpm install` + `pod install`(macOS) + 生成 `.env` |
| **`pnpm setup:env`** | 全平台 | 仅扫描本机工具路径，写入/更新 `.env`，并输出缺失项安装说明 |
| **`pnpm android`** | 全平台 | 通过 `with-env.js` **自动加载 `.env`** 后执行 `react-native run-android` |
| `bash scripts/setup.sh` | macOS / Linux | 等同于 `pnpm setup` |
| `.\scripts\setup.ps1` | Windows | 等同于 `pnpm setup` |

### 脚本文件说明

```
scripts/
├── setup.js              # 全平台安装入口（核心逻辑）
├── setup.sh              # Unix 壳，调用 setup.js
├── setup.ps1             # Windows 壳，调用 setup.js
├── setup-env.js          # 扫描 JAVA_HOME / ANDROID_HOME 等，生成 .env
├── with-env.js           # 加载 .env 后执行子命令（供 pnpm android 使用）
└── print-env-export.js   # 输出 export 语句，供当前 shell 使用
```

## 二、推荐流程（新同事 / 新机器）

### 1. 克隆仓库并安装 Node 依赖

```bash
pnpm install
```

### 2. 一键环境安装（全平台）

```bash
pnpm setup
```

将按平台尝试安装或检测：

| 组件 | macOS | Linux | Windows |
|------|--------|--------|---------|
| Node 18+ | Homebrew | apt / dnf / pacman | winget |
| JDK 17+ | Zulu / Temurin (cask) | openjdk-17-jdk 等 | Temurin / Microsoft JDK 17 |
| watchman | Homebrew（可选） | 包管理器（可选） | 可不装 |
| Android SDK 组件 | sdkmanager | sdkmanager | sdkmanager / Studio |
| Xcode | 检查是否安装 | — | — |
| CocoaPods | `pod install` | — | — |
| 项目依赖 | `pnpm install` | 同左 | 同左 |
| 环境文件 | 调用 `setup-env.js` → `.env` | 同左 | 同左 |

仅更新 `.env`、不装系统包：

```bash
pnpm setup -- --skip-system
# 或
pnpm setup:env
```

### 3. 启动开发

```bash
# 终端 1：Metro（须在 monorepo 根目录）
pnpm dev:mobile

# 终端 2：Android（自动读 .env）
pnpm android

# macOS：iOS
pnpm ios
```

## 三、`.env` 文件说明

- **模板**：`.env.example`（提交到 Git）
- **本机配置**：`.env`（由 `pnpm setup:env` 生成，**已在 `.gitignore`**）
- **旧脚本遗留**：`setup.sh` 曾写入 `.env.local`；当前以 **`.env`** 为准

### 变量一览

| 变量 | 是否必需 | 说明 |
|------|----------|------|
| `ANDROID_HOME` | Android 构建必需 | Android SDK 根目录 |
| `ANDROID_SDK_ROOT` | 建议与上一致 | 与 `ANDROID_HOME` 相同即可 |
| `JAVA_HOME` | Android 构建必需 | JDK 17+ 安装目录 |
| `REACT_NATIVE_PACKAGER_HOSTNAME` | 真机调试建议 | 开发机局域网 IP，供 Metro |
| `WEB_DEV_PORT` | 可选 | 独立 H5 端口，默认 `3000` |
| `WEB_DEV_URL` | 可选 | Web 开发地址 |
| `BRIDGE_TEST_WEB_URL` | 可选 | Bridge 测试页完整 URL |
| `ANDROID_AVD` | 可选 | 默认模拟器名称（`emulator -list-avds`） |

### 在当前终端手动加载 `.env`

**macOS / Linux：**

```bash
eval "$(node scripts/print-env-export.js)"
```

**Windows：**  
直接使用 `pnpm android` / `pnpm setup:env`（由 `with-env.js` 读取），无需手动 export。

### 重新扫描路径

安装完 JDK、Android Studio 或 SDK 组件后：

```bash
pnpm setup:env
```

## 四、RN 0.77 所需 Android SDK 组件

与 `android/build.gradle` 保持一致，安装脚本会尝试通过 `sdkmanager` 安装：

| 组件 | 版本 |
|------|------|
| Platform | `android-35` |
| Build-Tools | `35.0.0` |
| NDK | `27.1.12297006` |
| Platform-Tools | 最新 |

**Android Studio 路径：** SDK Manager → 勾选上述项。

**命令行（需已安装 cmdline-tools）：**

```bash
# macOS / Linux 示例
yes | "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" \
  platform-tools \
  "platforms;android-35" \
  "build-tools;35.0.0" \
  "ndk;27.1.12297006"
```

## 五、分平台安装指引（手动）

### macOS

```bash
# Homebrew
brew install node@22 watchman
brew install --cask zulu@17 android-studio   # 或 android-commandlinetools

# 环境
pnpm setup:env
pnpm setup          # 含 pod install

# 模拟器
emulator -list-avds
emulator @<AVD名称>
```

### Linux (Debian/Ubuntu)

```bash
sudo apt update
sudo apt install -y openjdk-17-jdk nodejs npm

# Android Studio 或 commandlinetools，设置 ANDROID_HOME
export ANDROID_HOME=$HOME/Android/Sdk

pnpm setup
```

### Windows

1. 安装 [Node.js LTS](https://nodejs.org/)
2. `winget install EclipseAdoptium.Temurin.17.JDK`
3. 安装 [Android Studio](https://developer.android.com/studio)，SDK 默认：`%LOCALAPPDATA%\Android\Sdk`
4. PowerShell 在项目根目录：

```powershell
pnpm install
.\scripts\setup.ps1
# 或
pnpm setup
pnpm android
```

## 六、常见问题

### 1. `spawn ./gradlew EACCES`

**原因：** `android/gradlew` 没有可执行权限。

**处理：**

```bash
chmod +x android/gradlew
# 或重新执行
pnpm setup:env
```

### 2. `Failed to launch emulator`

**原因：** 模拟器未就绪或 AVD 损坏。

**处理：**

```bash
# 先手动启动（名称见 .env 中 ANDROID_AVD）
emulator @Medium_Phone_API_36.0

# 再构建
pnpm android
```

### 3. 未检测到 JDK / `JAVA_HOME` 为空

**处理：** 按平台安装 JDK 17 后执行 `pnpm setup:env`。  
macOS：`brew install --cask zulu@17`

### 4. Metro 已运行但 Android 连不上

- 真机：确认 `.env` 中 `REACT_NATIVE_PACKAGER_HOSTNAME` 为电脑局域网 IP
- 模拟器：一般用 `localhost` / `10.0.2.2`（Android 模拟器访问宿主机）

### 5. iOS 图标显示为 `?`（SvgIcon）

- 确认 `ios/MyRnApp/Info.plist` 含 `UIAppFonts` → `MaterialIcons.ttf`
- **必须重新编译** iOS：`pnpm ios`（热更新不够）

### 6. `pnpm setup` 与 `pnpm setup:env` 区别

| | `pnpm setup` | `pnpm setup:env` |
|---|--------------|------------------|
| 安装系统工具 | ✅（可用 `--skip-system` 跳过） | ❌ |
| `pnpm install` | ✅ | ❌ |
| `pod install` | ✅（仅 macOS） | ❌ |
| 生成 `.env` | ✅（末尾调用 setup-env） | ✅ |
| 安装说明 | 简要 | **详细**（按缺失项打印） |

日常仅 PATH 变化时，执行 **`pnpm setup:env`** 即可。

## 七、与旧版 `setup.sh` 的关系

早期 `scripts/setup.sh` 为 **仅 macOS + Homebrew** 的一键脚本，并写入 `.env.local`。

当前方案：

- **跨平台逻辑** 已迁移至 `scripts/setup.js`
- **`setup.sh` / `setup.ps1`** 仅为薄封装
- 环境变量统一为根目录 **`.env`**

macOS 用户可继续使用：

```bash
bash scripts/setup.sh
```

效果等同于 `pnpm setup`。
