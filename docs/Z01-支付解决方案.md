接入国内的微信和支付宝支付，最大的痛点在于 App 端和 Web 端的唤起机制完全不同。App 端依赖原生 SDK 的 Scheme 唤起（App to App），而 Web 端则依赖浏览器重定向、H5 页面或微信内置环境（JSAPI）。

由于官方并未提供统一的 React Native 跨端 SDK，最优雅的解决方案是：**让后端作为核心大脑，前端（App/Web）根据平台只负责“分发渲染”或“直接传参唤起”**。

---

## 🛠️ 第一步：理清架构与后端的分工

不管是 App 还是 Web，**客户端绝对不要直接去调微信/支付宝的开放接口，更不要在前端计算签名**。

### 统一的业务流程：

1. **前端**：向**你的后端**发送请求：“我要买这个商品，我想用微信/支付宝”。
2. **后端**：根据前端请求的平台（App 还是 Web），向微信/支付宝服务器发起下单，**拿到对应平台的支付参数**，然后返回给前端。
3. **前端**：拿到参数后，根据平台执行不同的唤起动作。
4. **回调处理**：支付结果**绝对不要**以客户端的成功回调为准。必须等微信/支付宝的服务器异步通知（Webhook）到**你的后端**后，后端更新数据库，前端再通过轮询或 WebSocket 刷新订单状态。

---

## 📱 第二步：App 端的实现 (iOS / Android)

在纯原生 App 端，我们需要借助社区的桥接库来调用微信和支付宝的 SDK。

- **支付宝库推荐**：`react-native-alipay` 或 `@uiw/react-native-alipay`
- **微信库推荐**：`react-native-wechat-lib`

### 1. 支付宝 App 端逻辑

支付宝的处理非常简单，后端会生成一个极长的加签字符串（称为 `orderString`），前端直接扔给 SDK 即可。

```javascript
import Alipay from '@uiw/react-native-alipay';

const payWithAlipayApp = async orderId => {
  try {
    // 1. 从你的后端获取加签后的 orderString
    const {orderString} = await myApi.createAlipayOrder(orderId);

    // 2. 唤起支付宝 App
    const response = await Alipay.alipay(orderString);
    console.log('支付宝返回结果:', response);

    // 3. 提示：此时去后端轮询最终支付状态
  } catch (error) {
    console.error('支付宝唤起失败:', error);
  }
};
```

### 2. 微信 App 端逻辑

微信稍微复杂一点，需要在 App 启动时先初始化（注册 AppID），且后端返回的是一个包含多个字段的 JSON 对象。

```javascript
import * as WeChat from 'react-native-wechat-lib';

// App 启动时初始化（例如在 App.js 的 useEffect 中）
WeChat.registerApp('wx_your_appid', 'https://youruniversalLink.com/');

const payWithWechatApp = async orderId => {
  try {
    // 1. 从后端获取微信 App 支付参数
    const {payParams} = await myApi.createWechatOrder(orderId);

    // 2. 唤起微信 App
    const result = await WeChat.pay({
      partnerId: payParams.partnerid,
      prepayId: payParams.prepayid,
      nonceStr: payParams.noncestr,
      timeStamp: payParams.timestamp,
      package: payParams.package,
      sign: payParams.sign,
    });

    console.log('微信支付触发成功:', result);
  } catch (error) {
    console.error('微信支付失败:', error);
  }
};
```

## 🌐 第三步：Web 端的实现 (React Native Web)

在 Web 端，上面的原生库全都会失效。我们需要通过浏览器环境的处理来解决。

### 1. 支付宝 Web 端逻辑

支付宝在 Web 端非常简单。后端调用支付宝的 `alipay.trade.wap.pay`（手机网站支付）接口，会返回一段 **HTML 表单代码** 或者一个 **跳转 URL**。

- 如果返回的是 URL：前端直接 `window.location.href = url;`。
- 如果返回的是 HTML 表单：前端将其插入到页面中并自动 submit。

```javascript
const payWithAlipayWeb = async orderId => {
  // 后端直接返回一个跳转链接
  const {payUrl} = await myApi.createAlipayWebOrder(orderId);
  // 直接重定向，浏览器会自动唤起支付宝 H5 网页或引导唤起支付宝 App
  window.location.href = payUrl;
};
```

### 2. 微信 Web 端逻辑（重点坑区）

微信在 Web 端的策略完全取决于**用户的浏览器环境**：

- **场景 A：用户在微信内置浏览器内（公众号 H5）**
  不能用普通 H5 支付，必须使用 **微信 JSAPI 支付**。后端返回参数后，前端需要调用微信网页的 `WeixinJSBridge`。
- **场景 B：用户在普通浏览器内（如手机 Safari/Chrome）**
  需要使用 **微信 H5 支付（MWEB）**。后端调用微信接口，会返回一个形如 `[https://wx.tenpay.com/cgi-bin/mmpayweb-bin/checkmweb](https://wx.tenpay.com/cgi-bin/mmpayweb-bin/checkmweb)?...` 的链接，前端直接 `window.location.href = mweb_url`，浏览器会自动唤起微信 App。

```javascript
const payWithWechatWeb = async orderId => {
  // 检测是否在微信内置浏览器中
  const isWechatBrowser = /MicroMessenger/i.test(navigator.userAgent);

  if (isWechatBrowser) {
    // 场景 A：JSAPI 支付
    const {jsapiParams} = await myApi.createWechatJsapiOrder(orderId);

    // 调用微信浏览器的内置对象
    if (typeof WeixinJSBridge !== 'undefined') {
      WeixinJSBridge.invoke('getBrandWCPayRequest', jsapiParams, res => {
        if (res.err_msg === 'get_brand_wcpay_request:ok') {
          // 支付成功
        }
      });
    }
  } else {
    // 场景 B：普通浏览器 H5 支付
    const {mwebUrl} = await myApi.createWechatH5Order(orderId);
    // 重定向去唤起微信
    window.location.href = mwebUrl;
  }
};
```

## 🚀 第四步：优雅的多端封装 (组件层)

在你的 React Native 业务代码中，可以通过 `Platform.OS` 将上述两端的逻辑漂亮地桥接在一起：

```javascript
import {Platform} from 'react-native';

export const handlePayment = async (orderId, channel) => {
  if (Platform.OS === 'web') {
    // Web 端逻辑
    if (channel === 'alipay') {
      await payWithAlipayWeb(orderId);
    } else if (channel === 'wechat') {
      await payWithWechatWeb(orderId);
    }
  } else {
    // iOS / Android 原生端逻辑
    if (channel === 'alipay') {
      await payWithAlipayApp(orderId);
    } else if (channel === 'wechat') {
      await payWithWechatApp(orderId);
    }
  }
};
```

### ⚠️ 终极避坑提示（非常重要）

1. **iOS 的 Universal Links / URL Scheme**：微信 App 支付在 iOS 上必须配置好 `Associated Domains`（通用链接），否则在 iOS 13+ 以上系统唤起微信后会提示“未认证的 App”，甚至无法返回原应用。
2. **Web 端的 Referer 限制**：微信 H5 支付（MWEB）有严格的域名白名单限制。后端去微信下单时传入的域名，必须与你 Web 站点的实际域名完全一致，且浏览器跳转时必须携带正确的 `Referer` 请求头，否则会报错“商家参数格式有误”。
