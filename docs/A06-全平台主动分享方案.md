# 全平台主动分享统一方案

## 1. 概述

本方案旨在为 React Native 0.77 + Monorepo（pnpm workspace）项目提供**一套业务层 API 抹平 iOS、Android、HarmonyOS、移动端浏览器、PC 微信内置浏览器及桌面端浏览器**的分享能力差异。

核心原则：
- **业务层只调用一个函数**，无需关心底层平台差异
- **NativeShare 移动端方案 fork 到本地维护**，便于修复 UA 嗅探逻辑、补充新浏览器支持及微信 JSSDK 适配
- **尊重开源协议**，保留原作者引用与版权声明

---

## 2. 平台能力矩阵

| 平台 | 底层实现 | 唤起方式 | 限制 |
|------|---------|---------|------|
| **iOS / Android** | `react-native-share` | 主动唤起系统分享面板或指定 App | 无 |
| **HarmonyOS** | `@react-native-oh-library/react-native-share` | 主动唤起系统分享面板 | 需 ArkTS 侧注册 |
| **移动端浏览器** | `nativeshare` (fork) | 主动唤起微信/QQ/UC/系统分享 | 依赖 UA 嗅探 |
| **PC 微信内置浏览器** | 微信 JSSDK | **被动**：配置右上角菜单，用户手动点击 | 无法主动唤起 |
| **PC 其他浏览器** | `navigator.share` / 剪贴板 | 主动唤起系统面板或复制链接 | Firefox 不支持 Web Share API |
| **桌面端降级** | `@react-native-clipboard/clipboard` | 复制到剪贴板 | 需用户手动粘贴 |

### 4.3 原生端 (`native.ts`)

```typescript
import { ShareData } from './types';

export async function shareNative(data: ShareData): Promise<void> {
  let Share: any;

  try {
    // HarmonyOS 优先尝试鸿蒙化包
    Share = require('@react-native-oh-library/react-native-share').default;
  } catch {
    Share = require('react-native-share').default;
  }

  await Share.open({
    title: data.title,
    message: data.message,
    url: data.url,
  });
}
```

### 4.4 Web 端 (`web.ts`)

```typescript
import { ShareData, ShareTarget } from './types';
import { setClipboard } from './clipboard';

export async function shareWeb(data: ShareData, target?: ShareTarget): Promise<void> {
  const ua = navigator.userAgent.toLowerCase();
  const isMobile = /mobile|android|iphone|ipad/i.test(ua);
  const isWechat = /micromessenger/i.test(ua);
  const isWindowsWechat = isWechat && /windowswechat/i.test(ua);

  // 1. PC 微信内置浏览器：配置右上角菜单（被动分享）
  if (isWindowsWechat) {
    await setupPCWechatShare(data);
    notify('请点击右上角「···」分享给朋友');
    return;
  }

  // 2. 移动端浏览器（微信/QQ/UC/百度等）：用 NativeShare 主动唤起
  if (isMobile && (isWechat || /qq|ucbrowser|baidu/i.test(ua))) {
    const { NativeShare } = await import('@myapp/nativeshare'); // fork 后的本地包
    const ns = new NativeShare({
      wechatConfig: await fetchWechatConfig(), // 从后端获取 JSSDK 配置
      syncTitleToTag: true,
      syncDescToTag: true,
      syncIconToTag: true,
    });

    ns.setShareData({
      title: data.title,
      desc: data.message || '',
      link: data.url,
      icon: data.icon || '',
      from: '@myapp',
    });

    try {
      ns.call(target || 'default');
      return;
    } catch {
      // 不支持时继续降级
    }
  }

  // 3. 其他现代浏览器：Web Share API
  if (navigator.share && isMobile) {
    await navigator.share({
      title: data.title,
      text: data.message,
      url: data.url,
    });
    return;
  }

  // 4. 桌面端降级：复制到剪贴板
  await setClipboard(data.url);
  notify('链接已复制到剪贴板');
}

// PC 微信 JSSDK 配置（需先 setWechatConfigProvider）
async function setupPCWechatShare(data: ShareData) {
  const wx = await loadJWeixin();
  const config = await fetchWechatConfig();
  if (!config) return; // 未注入 provider 时跳过，走后续降级
  
  wx.config({
    ...config,
    jsApiList: ['updateAppMessageShareData', 'updateTimelineShareData'],
  });

  wx.ready(() => {
    wx.updateAppMessageShareData({
      title: data.title,
      desc: data.message,
      link: data.url,
      imgUrl: data.icon || '',
      success: () => console.log('PC WeChat share configured'),
    });
    wx.updateTimelineShareData({
      title: data.title,
      link: data.url,
      imgUrl: data.icon || '',
    });
  });
}

function loadJWeixin(): Promise<any> {
  return new Promise((resolve, reject) => {
    if ((window as any).wx) { resolve((window as any).wx); return; }
    const script = document.createElement('script');
    script.src = 'https://res.wx.qq.com/open/js/jweixin-1.6.0.js';
    script.onload = () => resolve((window as any).wx);
    script.onerror = reject;
    document.head.appendChild(script);
  });
}

// fetchWechatConfig 由 setWechatConfigProvider 注入，见 packages/share/src/wechatConfig.ts
```

### 4.5 剪贴板封装 (`clipboard.ts`)

```typescript
import Clipboard from '@react-native-clipboard/clipboard';

export async function setClipboard(text: string): Promise<void> {
  await Clipboard.setString(text);
}

export async function getClipboard(): Promise<string> {
  return Clipboard.getString();
}
```

## 5. 各平台依赖与配置

### 5.1 iOS / Android

```bash
pnpm add react-native-share
```

无需额外配置，Autolinking 自动处理。

### 5.2 HarmonyOS

```bash
pnpm add @react-native-oh-library/react-native-share
```

需在鸿蒙壳工程 `PackageProvider.cpp` 中注册包，并在 `module.json5` 中声明 `ohos.permission.INTERNET`。当前仓库尚无 `apps/harmony`，`native.ts` 已预留 try/require，待壳工程接入后联调。

### 5.3 Web 端

```bash
# 剪贴板
pnpm add @react-native-clipboard/clipboard

# NativeShare fork（见第 6 节）
# 通过 workspace 本地路径引入，不直接 npm install
```

**Webpack / Metro 配置**：
确保 Web 构建时 `@myapp/nativeshare` 指向 fork 后的本地路径。

```js
// metro.config.js / webpack.config.js
resolve: {
  alias: {
    '@myapp/nativeshare': path.resolve(__dirname, '../../packages/nativeshare/src/index.js'),
  },
}
```

## 6. NativeShare Fork 维护建议

**建议将 `fa-ge/NativeShare` fork 到 Monorepo 本地 `packages/nativeshare` 目录进行维护。**

### 6.1 为什么需要 Fork？

1. **UA 嗅探需要持续更新**：新浏览器（如鸿蒙自带浏览器、新版微信 WebView）的 UA 变化需要及时适配
2. **微信 JSSDK 配置需要业务定制**：原库的 `wechatConfig` 注入方式较原始，fork 后可接入统一的后端配置下发
3. **PC 微信浏览器支持**：原库未覆盖 `WindowsWechat` UA，fork 后可补充 PC 端微信 JSSDK 初始化逻辑
4. **TypeScript 化**：原库无类型定义，fork 后可补充 `.d.ts` 提升开发体验

### 6.2 Fork 规范

```bash
# 1. 从上游 fork（保留 Git 历史）
git clone https://github.com/fa-ge/NativeShare.git packages/nativeshare
cd packages/nativeshare
git remote rename origin upstream
git remote add origin <your-internal-git-repo>

# 2. 修改 package.json
{
  "name": "@myapp/nativeshare",
  "version": "1.0.0-fork.1",
  "description": "Forked from fa-ge/NativeShare - Unified mobile browser sharing",
  "license": "MIT",
  "repository": {
    "type": "git",
    "url": "https://github.com/fa-ge/NativeShare.git"
  },
  "author": "fa-ge (original), <your-team> (maintainer)"
}
```

### 6.3 建议的修改清单

| 修改项 | 说明 |
|--------|------|
| **补充 TypeScript 定义** | 添加 `index.d.ts`，导出 `NativeShare` 类及配置接口 |
| **补充 PC 微信 UA 判断** | 在内部 `_isWechat` 逻辑中增加 `WindowsWechat` 分支 |
| **微信 JSSDK 懒加载** | 原库要求外部传入 `wechatConfig`，fork 后可内置 `loadJWeixin` 逻辑 |
| **错误处理增强** | 原库 `call()` 失败直接抛异常，fork 后可返回更详细的错误码便于降级 |
| **ESM 构建输出** | 补充 `dist/esm` 输出，适配现代打包工具 |

## 7. 使用示例

```tsx
import { share } from '@myapp/share';
import { Button } from 'react-native';

function ShareButton() {
  const handleShare = async () => {
    await share({
      title: '邀请你加入',
      message: '快来体验全新功能',
      url: 'https://myapp.com/invite?code=123',
      icon: 'https://myapp.com/logo.png',
    }, 'wechatFriend'); // 指定目标，Web 端有效
  };

  return <Button title="分享给微信好友" onPress={handleShare} />;
}
```
