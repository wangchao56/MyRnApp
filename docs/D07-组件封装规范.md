# RN 项目组件封装规范

> 状态：✅ 已整理（2026-05-25）  
> 适用范围：`packages/shared` 中的全平台 UI 组件；`apps/mobile`、`apps/web` 中的业务页面组件可参照执行。

## 1. 目标与边界

### 1.1 设计目标

| 目标 | 说明 |
|------|------|
| **一次封装，多端复用** | 同一组件在 Metro（iOS/Android）、RNW（`apps/mobile` Web）、独立 H5（`apps/web`）中行为一致或可预期降级 |
| **业务与 UI 分离** | 可复用 UI 放在 `packages/shared`；页面编排、路由、Bridge 放在 `apps/*` |
| **类型安全** | Props、导出类型完整，通过 `@myapp/shared` 统一对外 |
| **可维护** | 目录结构、命名、平台拆分方式统一，便于 Code Review |

### 1.2 代码归属

```
packages/shared/src/
├── components/     # 全平台 UI 组件（本规范重点）
├── hooks/          # 与 UI/能力相关的 Hooks（平台拆分规则同组件）
├── theme/          # 主题、createStyleSheet、useStyles
├── utils/          # 纯工具（含 platformSelect、responsive）
└── ...

apps/mobile/src/    # 业务 Screen、导航、Bridge handlers
apps/web/src/       # 独立 H5 页面（React Router），可引用 @myapp/shared
```

**原则**：能在 `shared` 里复用的，不要写在 `apps` 里；仅单应用使用的组件放在对应 `apps/*/src/components`。

## 2. 目录与文件命名

### 2.1 组件目录结构

每个组件一个 **PascalCase** 目录，入口为 `index.tsx`（或平台拆分后的多个入口文件）。

**简单组件**（单文件即可）：

```
components/Button/
├── index.tsx          # 组件实现 + 默认导出
```

**中等复杂度**（类型/样式/子模块拆分）：

```
components/Scanner/
├── index.ts           # 对外 re-export，不堆业务逻辑
├── types.ts           # ScannerProps 等公共类型
├── Scanner.tsx        # 平台入口（转发到 .native / .web）
├── Scanner.native.tsx
├── Scanner.web.tsx
└── ScannerScreen.tsx  # 可选：带导航的复合 Screen
```

**平台实现差异大**（共用逻辑抽离）：

```
components/Gradient/
├── shared.ts          # 类型、工具函数、与平台无关的常量
├── index.tsx          # Native 实现
├── index.web.tsx      # Web 实现
```

### 2.2 命名约定

| 类别 | 约定 | 示例 |
|------|------|------|
| 目录名 | PascalCase | `SvgIcon/`、`OssImage/` |
| 组件名 | PascalCase，与目录一致 | `export const Button` |
| Props 接口 | 组件名 + `Props` | `ButtonProps`、`GradientProps` |
| 样式常量 | 小驼峰 + `Styles` 后缀 | `buttonStyles`、`iconStyles` |
| 平台文件 | 后缀区分平台 | `.web.tsx`、`.native.tsx`、`.ios.tsx`、`.android.tsx` |
| 示例/演示组件 | 后缀 `Example` | `ClipboardExample`、`SaveMediaExample` |
| 复合 Screen | 后缀 `Screen` | `ScannerScreen` |

### 2.3 禁止事项

- 不要在 `components/` 下使用无意义的 `utils.ts` 堆砌与组件无关的业务逻辑。
- 不要在 `index.ts` 桶文件中写组件实现（仅做 `export`）。
- 不要使用 `require()` 动态加载**仅 Native 可用**的库并依赖 `Platform.OS` 包裹（见 [§4](#4-平台差异处理)）。

## 3. 导出与对外 API

### 3.1 组件内导出

```tsx
// 推荐：命名导出组件 + 类型
export interface ButtonProps { /* ... */ }
export const Button: React.FC<ButtonProps> = (props) => { /* ... */ };
export default Button; // 可选，与命名导出二选一保持一致
```

### 3.2 包级桶文件

所有对外组件必须在 `components/index.ts` 中显式导出：

```ts
export { Button } from './Button';
export { Gradient, type GradientProps, type GradientDirection } from './Gradient';
```

应用层统一从 `@myapp/shared` 引用：

```tsx
import { Button, Gradient, createStyleSheet, useStyles } from '@myapp/shared';
```

### 3.3 对外 API 设计原则

1. **Props 扁平、语义清晰**：`variant`、`size`、`disabled` 等用联合类型约束，避免传入任意 `style` 掩盖设计 token。
2. **受控与非受控**：表单类组件明确 `value` / `onChange`；展示类避免强制业务 store 依赖。
3. **默认值在解构处声明**：`variant = 'primary'`，并在文档中说明。
4. **导出类型**：凡对外使用的 Props、枚举、工具函数类型，在 `components/index.ts` 中 `export type`。
5. **常量映射**：图标名等可提供 `ICONS` 常量对象（参考 `SvgIcon`），减少魔法字符串。

## 4. 平台差异处理

项目存在 **三条运行路径**，组件必须考虑解析与打包差异：

| 路径 | 命令 | 打包器 | 平台文件解析 |
|------|------|--------|----------------|
| 原生 App | `pnpm dev:mobile` / `android` / `ios` | Metro | 默认 `index.tsx`，无 `.web` 优先 |
| App RNW | `pnpm dev:mobile:web` | Rspack | 支持 `.web.tsx`（与 webpack 类似） |
| 独立 H5 | `pnpm dev:web` | Webpack | **优先** `.web.tsx` |

### 4.1 策略选择（按优先级）

```
1. 平台专属文件（首选，差异大或依赖原生模块）
      ↓ 无法实现时
2. Platform.OS / utils/platform.ts（小差异、一行判断）
      ↓
3. platformSelect({ ios, android, web, default })（多分支返回值）
```

### 4.2 平台专属文件

| 后缀 | 解析场景 | 典型用途 |
|------|----------|----------|
| `.web.tsx` | Webpack / Rspack 的 Web 构建 | CSS 渐变、html5-qrcode、localStorage |
| `.native.tsx` | Metro 默认；也可被 Web 构建在无 `.web` 时使用 | 相机、原生扫码、原生渐变库 |
| `.ios.tsx` / `.android.tsx` | 单平台原生差异 | 安全区、权限文案 |

**Webpack 解析顺序**（`apps/web/webpack.config.js`）：

```text
.web.tsx → .web.ts → .web.jsx → .web.js → .tsx → .ts → ...
```

**项目内参考实现**：

| 组件 | 模式 |
|------|------|
| `Gradient` | `shared.ts` + `index.web.tsx` + `index.tsx`（Native 用 `react-native-linear-gradient`） |
| `Scanner` | `Scanner.tsx` 转发 + `Scanner.web.tsx` / `Scanner.native.tsx` + `types.ts` |
| `useSaveMedia` | `useSaveMedia.ts` + `useSaveMedia.web.ts` |

### 4.3 ⚠️ 禁止：条件 require 原生库

**错误示例**（会导致 Webpack 静态分析仍打包原生库并报错）：

```tsx
// ❌ 不要这样写
let LinearGradientNative: any;
if (Platform.OS !== 'web') {
  LinearGradientNative = require('react-native-linear-gradient').default;
}
```

**正确做法**：使用 `index.web.tsx` / `index.tsx` 文件级拆分，Web 构建永远不会 `import` 原生-only 包。

### 4.4 小差异用 Platform API

适用于样式微调、无障碍属性等：

```tsx
import { Platform } from 'react-native';
import { isWeb, platformSelect } from '../utils/platform';

// 单行样式差异
paddingTop: Platform.OS === 'ios' ? 50 : 20,

// Web 无障碍
{...(Platform.OS === 'web' && { accessibilityRole: 'button' as any })}

// 多平台返回值
const iconSize = platformSelect({ ios: 24, android: 22, web: 20, default: 20 });
```

优先使用 `packages/shared/src/utils/platform.ts` 中的 `isWeb`、`isIOS`、`platformSelect`，避免散落魔法字符串。

### 4.5 原生依赖安装

- 仅 Native 使用的包：装在** monorepo 根目录** `package.json`，并在组件文档中注明 Android/iOS 额外配置（如字体 `fonts.gradle`）。
- 若 Web 完全不用：必须通过平台文件隔离，**不要**在 Web 入口链路上 import。
- 需要在 Web 上转译的 RN 生态包：加入 `apps/web/webpack.config.js` 的 `transpileModules` 列表。

## 5. 样式与主题

### 5.1 必须使用主题化 StyleSheet

```tsx
import { createStyleSheet, useStyles } from '../../theme';

const buttonStyles = createStyleSheet((theme) => ({
  button: {
    borderRadius: theme.borderRadius.md,
    paddingVertical: theme.spacing.sm,
    backgroundColor: theme.colors.primary,
  },
  text: {
    fontSize: theme.fontSizes.lg,
    fontWeight: theme.fontWeights.semibold as any,
    color: theme.colors.white,
  },
}));

export const Button: React.FC<ButtonProps> = (props) => {
  const styles = useStyles(buttonStyles);
  return <TouchableOpacity style={[styles.button, props.style]} />;
};
```

### 5.2 样式规则

| 规则 | 说明 |
|------|------|
| 颜色/间距/圆角 | 使用 `theme.colors.*`、`theme.spacing.*`，禁止硬编码品牌色（除渐变等业务色） |
| 数值尺寸 | `createStyleSheet` 内数值会自动 `fitSize` 适配；见 [D01-UI设计规范](./D01-UI设计规范.md) |
| 合并样式 | 使用数组：`style={[styles.base, condition && styles.active, style]}` |
| 静态无主题样式 | 可用 RN 自带 `StyleSheet.create`（如 `Gradient/shared.ts` 中仅 `overflow: 'hidden'`） |

详细用法见 [D02-主题化StyleSheet](./D02-主题化StyleSheet.md)。

### 5.3 Web 特有能力

Web 端可使用 CSS 能力（如 `backgroundImage: linear-gradient(...)`），放在 `.web.tsx` 或 `buildWebGradient` 类工具中，**不要**在 Native 文件里写 CSS 字符串。

## 6. TypeScript 与实现约定

### 6.1 组件类型

```tsx
import React from 'react';
import { ViewStyle } from 'react-native';

export interface MyComponentProps {
  children?: React.ReactNode;
  style?: ViewStyle;
  disabled?: boolean;
  onPress?: () => void;
}

export const MyComponent: React.FC<MyComponentProps> = ({
  children,
  style,
  disabled = false,
  onPress,
}) => {
  // ...
};
```

### 6.2 实现清单

- [ ] 使用函数组件 + Hooks，不使用 Class 组件
- [ ] Props 接口单独定义并导出
- [ ] 列表项/图标名等使用 `type` 联合或 `as const` 常量
- [ ] 避免 `any`；与 RN 类型冲突处局部断言（如 `fontWeight as any`）
- [ ] 副作用集中在 `useEffect`，清理函数处理订阅/定时器
- [ ] 不引入 `apps/*` 中的模块（shared 保持下层依赖）

### 6.3 Hooks 与组件的关系

| 场景 | 放置位置 |
|------|----------|
| 纯 UI、无状态 | 仅组件 |
| 可复用能力（剪贴板、扫码、保存媒体） | `hooks/`，平台拆分用 `.web.ts` |
| 全局状态、主题 | `hooks/useStore`、`theme/`，组件通过 `useTheme` / `useStyles` 消费 |

Hooks 同样在 `hooks/index.ts` 导出，命名 `useXxx`。

## 7. 组件分类与职责

### 7.1 基础展示组件

无业务、无网络，只负责 UI 与交互。

示例：`Button`、`Card`、`Input`、`SvgIcon`、`Gradient`

### 7.2 能力型组件

封装 Native API 或第三方 SDK，对外 Props 稳定。

示例：`Scanner`、`OssImage`、`ImagePreview`

要求：

- 在 `docs/` 下补充独立说明（或章节），标注各平台支持情况
- 失败时回调 `onError`，不静默吞错
- 权限类逻辑可配合 `useXxxWithPermission` Hook

### 7.3 示例组件（Example）

用于演示、联调，命名 `*Example`，**可不保证生产 API 稳定**。

示例：`ClipboardExample`、`SaveMediaExample`

### 7.4 复合 Screen

带导航、全屏布局的封装放在同一目录，命名 `XxxScreen.tsx`，由 `index.ts` 可选导出。

## 9. 新建组件流程（Checklist）

1. **确认归属**：是否放入 `packages/shared/src/components/`
2. **创建目录**：`ComponentName/index.tsx`（及 `types.ts`、`shared.ts` 如需要）
3. **评估平台**：是否需要 `.web.tsx` / `.native.tsx`
4. **实现样式**：`createStyleSheet` + `useStyles` + theme token
5. **导出**：`components/index.ts` + 必要时 `packages/shared/src/index.ts` 已 re-export
6. **原生依赖**：根目录安装 + 文档写明 Gradle/Pod 步骤
7. **编写文档**：`docs/Dxx-*.md`，更新 [docs/README.md](./README.md) 索引
8. **三端验证**：Metro / Webpack /（可选）Rspack

## 10. 反模式速查

| 反模式 | 后果 | 正确做法 |
|--------|------|----------|
| `if (Platform.OS !== 'web') require('native-lib')` | Webpack 仍打包原生库，构建失败 | 平台文件拆分 |
| 在 shared 中 import `apps/mobile` 代码 | 循环依赖、无法复用 | 依赖倒置，回调/Bridge 由 app 注入 |
| 硬编码 `#007AFF` 等颜色 | 深色模式不一致 | `theme.colors.*` |
| 巨型单文件 500+ 行 | 难维护 | 拆 `types` / `shared` / 子组件 |
| 仅改 Native 未测 `pnpm dev:web` | H5 回归 | 组件规范默认三端自检 |
| Example 组件当生产 API |  Breaking 风险 | 业务用稳定 Props 的正式组件 |
